## 如果要做某个功能，你会怎么设计 Agent 流程？（开放设计题）

**来源：** 字节AI Agent面试经验（已Offer）

### 核心要点

- **澄清需求：** 目标用户、成功标准、约束（延迟、成本、合规）、是否需 Human-in-the-loop。
- **拆解：** 是否需要 RAG？哪些步骤用 tool？哪些用纯 LLM？能否 workflow 固化部分路径？
- **架构：** Router → Planner（可选）→ Agent loop（ReAct）→ Tools → Memory → Eval hook。
- **风险：** 幻觉、越权、成本爆炸、死循环——逐一给 guardrail。
- **MVP：** 先单 Agent + 2–3 tools + 小 knowledge base，再扩展 multi-agent。

### 与前端工程结合的角度

- 从用户旅程反推：入口（chat / 表单 / 嵌入式）→ 关键确认 UI → 结果展示（含 citation）。
- 前端可先做「假 Agent」wizard 验证 UX，再接入真实 LLM。

### 面试加分项

- 用 5 分钟 whiteboard：框图 + 2 个 tool schema 示例。
- 主动问面试官业务域（客服 vs 研发效能）再定制答案。

## 简历上的 Agent 项目会被如何追问？如何准备？

**来源：** 字节AI Agent面试经验、大模型算法面试八股总结

### 核心要点

- **趋势：** 大厂体感上「纯背八股」权重下降，**主线围绕个人经历与项目深挖**；八股用于支撑你能讲清原理，而非替代项目故事。
- **追问方向：** 为什么选这个架构？最大 bug 是什么？如何 eval？成本多少？如果重做会改什么？
- **准备材料：** 架构图、关键代码路径、metrics dashboard、3 个 deep dive story（成功 / 失败 / 权衡）。
- **诚实：** 说清哪些是团队分工、个人贡献；AI 辅助代码要懂原理。

### 与前端工程结合的角度

- 准备 demo 脚本（2 分钟 / 5 分钟两版）；前端 highlight：SSE、tool UI、性能优化数字。

### 面试加分项

- STAR 法则讲一个「检索不准 → hybrid + rerank → Recall 提升」故事。
- 带 notebook 本地可 run 的 minimal repro。

## 对目标公司 AI 产品的了解（开放题）

**来源：** 某大厂 RAG+Agent 面经

### 核心要点

- **准备：** 试用产品（豆包、Coze、企业微信智能助手、字节的 xxx）；读官方 blog / 发布会；**摸清目标部门业务域**（面试开放题常考「若做某功能你怎么设计 Agent 流程」）。
- **分析框架：** 目标用户、核心 Agent 能力、知识库 / 插件生态、差异化、明显短板。
- **连接自身：** 「贵司 XX 场景我会用 Agentic RAG + HITL，因为……」

### 与前端工程结合的角度

- 从 UI/UX 角度 critique：streaming 体验、tool 透明度、引用溯源是否清晰。
- 提 constructive 改进建议而非纯吹捧。

### 面试加分项

- 对比竞品 table（功能 / 定价 / 开发者体验）。
- 引用具体版本更新（如某月上线 multi-agent）。

## Text2SQL / NL2SQL 业务如何提升识别准确率？（项目落地）

**来源：** 字节AI Agent后端面经、外某企 agent 面经

### 核心要点

- 见 LLM 基础篇 Text2SQL 条目；项目层补充：
- **业务词典：** 指标别名、口语 → 标准字段 mapping 表。
- **Schema pruning：** 大库只暴露相关 5–10 张表。
- **Execute-verify loop：** SQL 报错自动修正；结果空集 ask user clarify。
- **权限：** 行级权限注入 SQL filter 或 middleware。

### 与前端工程结合的角度

- SQL 预览 + 语法高亮 + 「影响行数估算」+ 用户 confirm 后再跑。
- 图表 auto viz（根据 result schema 推荐 bar/line/table）。

### 面试加分项

- 项目数据：准确率从 60% → 85% 的 ablation（schema linking + few-shot + self-correction）。
- 安全 story：阻止 `DROP TABLE` 的 parser 层拦截。

## RAG 实际落地过程中最大难点是什么？（结合项目答）

**来源：** 字节AI Agent后端面经

### 核心要点

- **常见答案：** 检索质量（chunk、hybrid、rerank）> 生成；文档质量参差；eval 难；权限与数据更新。
- **展开：** 举一个真实 bad case：如「法条跨条引用检索不到」→ 父子索引 + metadata + query rewrite 解决。
- **组织：** 跨团队（法务提供标注、工程建 pipeline、前端做 feedback UI）。

### 与前端工程结合的角度

- 难点之一是「用户不知道 AI 不知道什么」→ 前端应用 citation + 空结果 UX 管理预期。

### 面试加分项

- 量化 before/after；说明 still not solved 的问题（多跳推理、表格数值）。

## 抑制幻觉：项目中具体做了什么？

**来源：** 字节AI Agent后端面经

### 核心要点

- **组合拳：** RAG grounding + 强制 citation + 无 source 则拒答 + temperature 0 + self-check prompt + 人工 spot audit。
- **Eval：** faithfulness 指标 weekly 回归。
- **产品：** 显示 confidence / 「仅供参考」免责声明。

### 与前端工程结合的角度

- 每条 claim 绑定 source chip；点击跳转原文 highlight。
- 「未在知识库找到」专用 empty state 文案。

### 面试加分项

- 对比微调 alone 无法解决知识更新问题。
- CRAG / Self-RAG 是否评估过。

## Agent 平台 vs 工作流平台：企业选型场景题

**来源：** 某大厂 RAG+Agent 面经

### 核心要点

- **选工作流：** 财务审批、固定 SLA、强审计、步骤 100%  predetermined。
- **选 Agent：** 研发问答、数据分析探索、客服复杂意图、需 multi-tool 自适应。
- **混合：** 工作流节点内嵌 Agent 子流程（如「自动生成审批摘要」一步用 LLM）。

### 与前端工程结合的角度

- 前端团队可能两套 UI 都要做：拖拽 workflow editor + chat copilot；组件复用（节点 status、log viewer）。

### 面试加分项

- 企业落地路径：先 workflow 自动化，再 Agent 增强 intelligent steps。

## 企业级 Agent 落地 checklist（场景题）

**来源：** 某大厂 RAG+Agent 面经、工程化实践

### 核心要点

- **安全：** SSO、RBAC、audit、prompt injection 防护、tool sandbox。
- **质量：** offline eval + online feedback + regression gate。
- **成本：** token budget、rate limit、模型路由（小模型 triage + 大模型复杂任务）。
- **运维：** trace、alert、降级（纯 FAQ / 人工客服）。
- **合规：** 数据 residency、PII 脱敏、 retention policy。

### 与前端工程结合的角度

- Admin console：租户配置、quota、feature flags、audit log 搜索。

### 面试加分项

- 引用 SOC2 / 等保要求如何映射到 Agent 架构。
- 说明 on-call runbook：模型 API 挂了怎么办。

## LLM 评测、RAG、Prompt 优化：外企 Agent 面常见综合题

**来源：** 外某企A - agent -一面

### 核心要点

- **LLM 评测：** capability benchmark + 业务 golden set + LLM-as-Judge 局限性。
- **RAG：** 全链路 + Recall/ Faithfulness 指标 + bad case 迭代。
- **Prompt：** 结构化、few-shot、版本管理、A/B；与 context engineering 分工。
- **表达：** 逻辑清晰、先框架后细节、承认 tradeoff。

### 与前端工程结合的角度

- 展示 internal eval dashboard screenshot（脱敏）作为 project evidence。
- Prompt 迭代工具若前端自建，可讲 workflow。

### 面试加分项

- 英文面试准备 30 秒 elevator pitch for your Agent project.
- 外企重视 responsible AI：bias、privacy、human oversight。

## 数据处理场景：大批量任务的 Agent 设计模式

**来源：** 快手AI Agent开发一面（千条求和）、Skill 复杂逻辑

### 核心要点

- **模式：** map-reduce — Agent 生成 plan → code tool 分批处理 → aggregate → validate。
- **禁止：** 把大量 raw data 塞进 context。
- **工程：** 队列（SQS / Redis stream）、进度 callback、失败 batch 重试。
- **Agent 角色：** 理解意图、选策略、解释结果；计算交给 deterministic code。

### 与前端工程结合的角度

- Progress bar（45/1000 batches）；partial result 表格预览。
- WebSocket 推送 batch 完成事件。

### 面试加分项

- 对比 Temporal workflow vs Agent loop 长任务可靠性。
- 给出复杂度分析：O(n) single pass vs 错误分批代价。

## 「Agent + 机器学习基础」：前端转型需补哪些课？

**来源：** 字节AI Agent面试经验、算法面经、大模型算法面试八股总结

### 核心要点

- **知识图谱（算法面常按模块展开）：**

  | 模块 | 典型考点 | 前端转型优先级 |
  | --- | --- | --- |
  | LLM 训练 | 预训练 / SFT / RLHF、Tokenizer、注意力 | 懂概念即可 |
  | RL 算法 | MDP、Policy Gradient、PPO、奖励设计 | 选补 |
  | Agentic RL | 多步工具轨迹 RL、GRPO、任务完成率奖励 | 了解名词与代表工作 |
  | Infra | 分布式训练、推理加速、GPU 调度、网关 | 结合工程化与部署篇 |
  | Agent 框架 | ReAct、LangGraph、RAG、MCP、eval | **主攻** |

- **必补：** Transformer 基本概念、embedding、解码参数、RAG 链路、ReAct、function calling、eval 指标。
- **选补：** RLHF 原理、MoE、Scaling Laws（面试算法岗更深）。
- **不必：** 手推反向传播、自己训 70B（除非岗位 JD 明确要求）。

### 与前端工程结合的角度

- 用「能讲清项目里模型怎么选、检索怎么调、失败怎么 debug」为标准，而非数学推导。

### 面试加分项

- 28 天学习计划式节奏：hello-agents + 一个小 demo + 每日 2 题八股（见相关笔记资源）。
- 展示 learning in public：复习指南 / 博客就是证据。

## CoT 与 ReAct 在项目选型中怎么拍板？

**来源：** 字节AI Agent后端面经

### 核心要点

- **纯推理、无外部数据：** CoT 或 single-shot prompt。
- **需查库、调 API、写文件：** ReAct（或 LangGraph tool node）。
- **复杂项目：** Planner(CoT) + Executor(ReAct)；前端展示 plan 再 execution。

### 与前端工程结合的角度

- UI 上 CoT-only 可隐藏 tool 区；ReAct 必须预留 tool timeline 高度。

### 面试加分项

- 用项目真实 qps / latency 数据说明选型后果。

## 手写 Agent vs 框架：面试中如何答才不极端？

**来源：** 字节AI Agent后端面经

### 核心要点

- **立场：** 框架加速原型；生产核心 path 自研或 LangGraph 显式图；避免 LangChain 黑盒堆叠。
- **因素：** 团队熟悉度、debug 需求、vendor lock-in、合规审计。
- **前端类比：** Next.js vs 自研 SSR——按阶段选。

### 与前端工程结合的角度

- 你负责的是 UI + API 契约稳定；后端换框架不应逼前端大改——contract-first 设计。

### 面试加分项

- 具体说 LangGraph checkpoint 如何解决你们 resume 需求，而纯 LangChain AgentExecutor 做不到。

## 大厂 Agent / 大模型岗位近年面试考察趋势是什么？

**来源：** Agent 开发高频面试题（八股版）、大模型算法面试八股总结、字节 AI Agent 面试经验（已 Offer）

### 核心要点

- **考察面变宽：** 不再只问传统后端八股，**AI 基础 + Agent 工程 + 部分算法** 常同场出现（实习 / 校招尤甚）；字节 Agent 岗仍要求 **Agent + ML 基础** 过关，但追问落在项目落地。
- **深度在项目：** 面试官更愿意沿简历追问「你怎么设计、怎么排障、怎么 eval」，而非孤立背定义；**亲手项目 + 可运行网页** 是一面常见门槛。
- **流程体验：** 大厂 Agent 岗反馈链通常较快（面经：投递→一面约 1 周内、多轮隔天约），适合准备 **2 分钟 / 5 分钟** 两版 Demo 脚本随时开讲。
- **分层准备：**
  - **应用 / 前端向：** Agent 架构、RAG、工具调用、流式 UI、安全与限流、可观测性。
  - **算法向：** 在上述基础上加深 LLM 训练、RL / Agentic RL、推理优化。
- **系列帖常见盲区：** 小红书「八股合集」类笔记多为预告，正文无具体题面——复习应以可深挖的项目故事 + 本指南题单为主。

### 与前端工程结合的角度

- 用「一个完整 Agent demo + 2 分钟架构讲解 + 1 个失败复盘」覆盖 70% 应用岗追问；八股用来回答「为什么这样设计」的 follow-up。
- 投 Agent 应用岗时，主动把叙事落在 **用户体验、契约稳定性、HITL、成本可见性**，而非抢算法岗的训练细节。

### 面试加分项

- 开场 30 秒说清目标岗位（应用工程 vs 算法研究），引导面试官提问方向。
- 提到你如何用 eval 数据集 / trace 面板证明迭代有效，比罗列「看过 XX 论文」更有说服力。
