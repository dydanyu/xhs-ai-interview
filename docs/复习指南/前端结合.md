## 面试时如何展示 Agent 项目？（投屏演示与 README）

**来源：** 字节 AI Agent 面试经验（已 Offer）

### 核心要点

- **可运行 Demo：** 有能跑起来的 Web 前端是显著加分项；字节一面常直接要求**投屏 walkthrough**。
- **README 深度：** 系统架构图、数据流、关键设计决策及 tradeoff、已知局限、如何 eval——面试官会**抠每个设计决策的原因**。
- **吃透细节：** 即使用 AI 辅助写码，也要能解释「为什么 ReAct 而非 Plan-only」「为什么 hybrid search」；创意类项目（如 AI Native 游戏）易被**逐模块深挖**。
- **准备 PPT / 架构图：** 应对深挖记忆、工具、RAG；临时可用项目 PPT 救场。
- **业务前置调研：** 开放题「若做某功能你怎么设计 Agent 流程」需结合**目标部门业务**作答；Offer 后 Leader/Mentor 沟通也是了解方向的样本——面试前应主动试用目标公司产品、读官方 blog。

### 与前端工程结合的角度

- 前端工程师优势：快速做 Chat UI + tool trace + 知识库管理后台，形成完整 product story。
- 部署 Vercel / 内网 demo link，面试前测通链路（SSE、CORS、API key）。

### 面试加分项

- Live demo fallback：预录 video 防网络翻车。
- Open source + 在线 demo + eval 数字（task success 85%）三位一体。

## 前端在 AI Agent 系统中的职责边界？

**来源：** 综合面经（字节、快手、Agent 工程岗共识）

### 核心要点

- **交互层：** 对话 UI、流式渲染、markdown / code highlight、citation 展示、tool call 可视化。
- **人机协作：** 确认门、参数编辑、interrupt/resume、feedback（👍👎）。
- **配置层：** Prompt 模板选择、知识库上传、Skill 开关、模型参数 preset。
- **可观测：** 开发者模式 trace、token 用量、latency waterfall。
- **不负责：** 模型训练、向量索引底层（但需懂接口契约）。

### 与前端工程结合的角度

- 复用组件：MessageList、ToolCallCard、SourceCitation、PlanSteps、ErrorBoundary for SSE。
- 状态管理：区分 streaming partial state vs committed messages；Optimistic UI for user sends。

### 面试加分项

- 熟悉 Vercel AI SDK、CopilotKit、assistant-ui 等生态。
- 说明 SSR vs 纯 CSR 在 Agent UI 的选择（通常 CSR + SSE）。

## 流式输出（SSE）与 Agent UI 状态机如何设计？

**来源：** Agent 工程实践（前端核心场景）

> SSE 解析完整实现见 [手写代码题 · SSE 流式响应解析器](手写代码题.md#sse-流式响应解析器)。

### 核心要点

- **事件类型：** text_delta、tool_call_start、tool_result、plan_update、error、done。
- **状态机：** idle → streaming → tool_running → streaming → done / error；支持 abort。
- **渲染：** 增量 markdown parse（注意 half-open code block）；tool 与 text 交错展示。
- **可靠性：** 断线重连、message id 幂等、后端 checkpoint 恢复会话。

### 与前端工程结合的角度

- 用 `ReadableStream` + `EventSource` / fetch SSE；React Suspense 谨慎用于 streaming。
- loading skeleton 区分「模型在想」vs「工具执行中（可能 10s+）」。

### 面试加分项

- 提到 OpenAI streaming tool_calls 的 index 合并逻辑。
- UX：长时间 tool call 显示 cancel + 进度（若 tool 支持 progress callback）。

```typescript
type AgentPhase = "idle" | "streaming" | "tool_running" | "done" | "error";
// SSE 事件驱动状态机；tool_running 时展示独立 loading，避免用户以为卡死
function onEvent(e: { type: string }) {
  if (e.type === "tool_call_start") setPhase("tool_running");
  if (e.type === "text_delta") setPhase("streaming");
}
```

## Human-in-the-loop 确认 UI 如何设计？

**来源：** Function Calling 可靠性、工具安全（全攻略下 + 快手面经）

### 核心要点

- **触发条件：** 写操作、外发、支付、权限变更、低 confidence 决策。
- **UI 要素：** 操作摘要、影响范围、参数可编辑、Confirm / Cancel / Edit。
- **超时：** 未确认则 agent pause，state 持久化；resume 后继续 graph。
- **审计：** 记录用户 confirm 时间与修改后参数。

### 与前端工程结合的角度

- Modal / Drawer 阻断式确认 vs inline diff 非阻断；高风险用 Modal。
- 与现有 design system 的 Button danger variant 一致。

### 面试加分项

- LangGraph interrupt API 与前端 resume token 对接经验。
- 无障碍：focus trap、键盘确认。

## Agent Trace / Debug 面板前端如何实现？

**来源：** 工程化 observability 需求

### 核心要点

- **展示：** 每轮 LLM input/output tokens、tool calls、latency、retrieved chunks。
- **用户：** 内部 debug 模式；对普通用户仅展示 simplified step list。
- **技术：** OpenTelemetry trace id 贯穿；前端按 trace 拉 span 树。

### 与前端工程结合的角度

- 折叠树组件 + JSON viewer（react-json-view-lite）；敏感字段 redact。
- Feature flag 控制仅 admin 可见。

### 面试加分项

- 集成 LangSmith / Langfuse iframe 或自研轻量版。
- 从 trace 一键「复制为 eval case」。

**来源：** 某大厂 RAG+Agent 面经、RAG 链路

### 面试加分项

- 检索测试台帮助非算法同学调 RAG。

## Prompt 注入与 XSS：前端防护要点？

**来源：** Prompt 注入防御

### 核心要点

- **渲染：** model output markdown 需 sanitize（DOMPurify）；禁止 arbitrary HTML。
- **用户输入：** 不作为 HTML 插入；paste 消毒。
- **链接：** `rel="noopener noreferrer"`；警告外链。
- **CSP：** 限制 inline script；SSE endpoint 同源或 CORS 严格。

### 与前端工程结合的角度

- 前端是最后一道 XSS 防线；尤其 citation 可能含恶意 title。
- 不在 localStorage 存 API key；用 httpOnly cookie 或 backend proxy。

### 面试加分项

- 说明 markdown 中 `<img onerror=...>` 类攻击向量。
- MCP browser tool 返回 untrusted HTML 时的 sandbox iframe 展示。

## 前端如何参与 Agent Eval 与反馈闭环？

**来源：** RAG/Agent 评测面经

### 核心要点

- **采集：** thumbs up/down、重新生成、编辑后发送（implicit correction）。
- **标注：** 内部工具标记 bad retrieval / wrong tool / hallucination。
- **A/B：** feature flag 分流不同 prompt / UI variant，埋点 task completion。

### 与前端工程结合的角度

- Feedback widget 轻量不打断对话；optional comment。
- 将 user edited answer 作为 preference data 回流（需 consent）。

### 面试加分项

- 与 PostHog / Mixpanel 事件设计。
- 说明 frontend metrics 如何 correlate 后端 eval scores。

## TypeScript 类型与 Tool Schema 一体化？

**来源：** Function Calling 设计、前端工程师优势

### 核心要点

- **Single source of truth：** Zod schema → JSON Schema → OpenAI tools + 前端表单校验。
- **类型安全：** tool handler `satisfies` schema；减少 hand-written JSON。
- **版本：** schema v2 时 frontend / backend 同步 bump。

### 与前端工程结合的角度

- monorepo packages/shared-tools 导出 schema 与 types。
- openapi-typescript 或 trpc 若工具走 REST。

### 面试加分项

- 举例 zod-to-json-schema 流水线脚本 CI 校验。
- 运行时 ajv validate + compile-time zod 双保险。
